# Lua API: `omegga.brickadia` (`BR`)

```lua
local BR = require("omegga.brickadia")   -- any mod; the bridge's `exec` has it as the global BR
```

The `BR` helpers and recipes were all run on a server. All of them touch UObjects, so call them
on the game thread: from `Omegga.handle` handlers, `exec`, `ExecuteInGameThread` or `RegisterHook`
callbacks, never directly from a `LoopAsync` body.

Values that are opaque engine structs travel as Lua strings of raw bytes: a brick handle is 8
bytes, a builder 0x38, a port ref 8, a wire value 0x28. Treat them as tokens; layouts are in
[brickadia-internals.md](brickadia-internals.md).

## Editor completion

Completion works with [Lua Language Server](https://luals.github.io/) (the "Lua" extension in
VS Code, or `lua_ls` in Neovim). It draws on three sets of annotations:

| Where | What |
|--|--|
| `types/omegga.lua` in this plugin | `BR`, `Omegga`, the native helpers |
| `types/ue4ss.lua` in this plugin | UE4SS's own globals and base classes (`UObject`, `RegisterHook`, ...), as UE4SS ships them |
| `data/UE4SS/Mods/shared/types/` | every class, function, property and enum the game had loaded, generated by UE4SS |

The plugin generates the third set after the first map loads, and again only after the game binary
changes (it compares the binary against `.binary` in that folder). The output follows
whatever classes are loaded at the time, so delete `.binary` and restart to regenerate after
a map that loads more. `GenerateLuaTypes()` in any mod or `exec` regenerates it immediately.
Don't put your own files in that folder: the generator deletes every `.lua` file there first.

The first start also writes `data/Mods/.luarc.json`, which points the language server at all
three, so opening `data/Mods` in an editor just works. It is left alone once it exists. For a
mod shipped by an omegga plugin, give the plugin's `mods/` folder the same settings with the
paths for that server:

```json
{
  "runtime.version": "Lua 5.4",
  "workspace.library": ["<omegga>/plugins/ue4ss/types", "<omegga>/data/UE4SS/Mods/shared/types"],
  "workspace.preloadFileSize": 4096
}
```

`require` returns untyped values to the language server, so annotate the two modules:

```lua
---@type BRModule
local BR = require("omegga.brickadia")
---@type OmeggaModule
local Omegga = require("omegga")

local pc = FindFirstOf("BP_PlayerController_C") ---@cast pc ABP_PlayerController_C
```

## World

| | |
|--|--|
| `BR.ready()` | true once the global brick grid exists (map loaded) |
| `BR.world_context()` | the game `UWorld`, which `WorldContextObject` params need |
| `BR.global_grid()` | the `GlobalBrickGridActor` |
| `BR.game_mode()` | the `BRGameModeBase` |

These raise a Lua error instead of returning an invalid object.

## Bricks

| | |
|--|--|
| `BR.asset(name)` | a brick asset by name: `"PB_DefaultBrick"`, `"B_Bot_Spawn_Point"`, `"B_1x1_Gate_Expr_LogicalAND"` |
| `BR.builder(opts)` | builder bytes. `opts`: `asset`, `size = {x, y, z}` (procedural bricks; half-extents in brick units), `color = {r, g, b, a}`, `material` (a `BR.MATERIAL` name such as `"Glass"`, or its number; default `"Plastic"`), `alpha` (default 5), `grid`, `owner` (brick owner index), `visible = false`, `collision = false` |
| `BR.MATERIAL` | `Plastic`, `Glass`, `TranslucentPlastic`, `Glow`, `Metal`, `Hologram` (`EBrickMaterial`) |
| `BR.place(builder, x, y, z, orientation?)` | handle, or nil when refused. Immediate, no trust check, no undo. `orientation` defaults to `BR.Z_UP` |
| `BR.brick_info(handle)` | `{ valid, asset, position = {x, y, z} }`, or `{ valid = false }` |
| `BR.brick_valid(handle)` | whether the handle names a live brick |
| `BR.brick_id(handle)` | persistent id bytes, for transactions |
| `BR.is_visible(handle)` | bool |
| `BR.brick_count(grid?)` | number of bricks |

Brick helpers check the handle first and raise a Lua error for a dead one: the game's own
brick functions abort the server on an invalid handle.

Positions are integer brick units, and sizes are half-extents: `size = {10, 10, 6}` with `z = 6`
sits on the baseplate. Orientations: X+ 0..3, X- 4..7, Y+ 8..11, Y- 12..15,
Z+ 16..19, Z- 20..23.

### Recipes

Tested:

```lua
-- a red brick
local h = BR.place(BR.builder({ asset = "PB_DefaultBrick", size = { 10, 10, 6 }, color = { 255, 0, 0, 255 } }), 0, 0, 6)

local L = "BRLuauBrickLibrary"
local lib = StaticFindObject("/Script/Brickadia.Default__BRLuauBrickLibrary")
local w = BR.ptr(BR.world_context())

-- recolour (FColor bytes are B, G, R, A)
BR.call(lib, L, "SetColor", { Self = h, NewColor = string.pack("BBBB", 0, 255, 0, 255), WorldContextObject = w })
-- move
BR.bool(BR.call(lib, L, "TryMove", { Self = h, NewPosition = BR.ivec(0, 0, 30), WorldContextObject = w }).ReturnValue)
-- delete
BR.call(lib, L, "DeleteBrick", { Self = h, WorldContextObject = w })

-- find a brick in a box
local grid = StaticFindObject("/Script/Brickadia.Default__BRLuauGridLibrary")
local r = BR.call(grid, "BRLuauGridLibrary", "FindInBox", { Self = BR.ptr(BR.global_grid()), Min = BR.ivec(-10, -10, 0), Max = BR.ivec(10, 10, 40) })
if BR.bool(r.ReturnValue) then print(BR.brick_info(r.OutBrick).position[3]) end

-- every brick: a TArray of 8-byte handles {data, num, max}
local data, num = string.unpack("<I8i4", BR.call(grid, "BRLuauGridLibrary", "GetBricks", { Self = BR.ptr(BR.global_grid()) }).ReturnValue)
for i = 0, num - 1 do local handle = __peek(data + i * 8, 8) end
```

## Components, gates and wires

| | |
|--|--|
| `BR.component_types()` | every registered component type object (about 400) |
| `BR.component_type(name)` | by transient name (`"BrickComponentType_Expr_LogicalAND"`) or part of a Blueprint type's name (`"BotSpawn"`, `"Component_BrickPropertyChanger"`) |
| `BR.ports(type)` | `{ inputs = {...}, outputs = {...} }`: the port FNames refs use |
| `BR.input_port(type, port)` / `BR.output_port(type, port)` | port ref bytes |
| `BR.wire_bool(v)`, `BR.wire_int(v)`, `BR.wire_double(v)`, `BR.wire_string(text)` | wire value bytes |
| `BR.player()` | the PlayerState Lua acts as: transactions, admin gates, its own bricks ([why](brickadia-internals.md#transactions-and-trust)). Not in `BR.players()` |
| `BR.owner_index()` | that player's brick owner index; place bricks you'll edit with `owner = BR.owner_index()` |
| `BR.transaction(player, fn)` | run `fn(tx)` to record actions, execute, return the report counters and `lines` (messages such as admin gate refusals) |
| `BR.changes(report)` | only the non-zero counters, and `lines` if any |
| `BR.set_input(handle, type, port, value)` | one-action transaction; returns the report |
| `BR.input_is(handle, type, port, value)` | read an input back: true if it already holds `value`. If not, it now does |

`tx` records: `tx.set(id, inputPort, wireValue)`, `tx.connect(srcId, outputPort, dstId, inputPort)`,
`tx.attach(id, componentType)`, `tx.delete(id)`. Report counters: `BricksPlaced`,
`BricksUntrusted`, `ComponentsChanged`, `ComponentsSkipped`, `ComponentsAttached`,
`WiresConnected`, ... (all 34 in `REPORT_FIELDS`).

Port names are the component's property names, not display names: LogicalAND has `bInputA`,
`bInputB` → `bOutput`; MathAdd `InputA`, `InputB` → `Output`. Use `BR.ports` to find them. Use
the port's own kind: numbers are doubles (`wire_double`); an integer written to a double input
counts as a different value.

### Recipes

Tested; setting and reading a gate input is also in the acceptance run.

```lua
local AND, ADD = "BrickComponentType_Expr_LogicalAND", "BrickComponentType_Expr_MathAdd"
local ps, owner = BR.player(), BR.owner_index()

-- two AND gates, the first feeding the second
local a = BR.place(BR.builder({ asset = "B_1x1_Gate_Expr_LogicalAND", owner = owner }), 0, 0, 6)
local b = BR.place(BR.builder({ asset = "B_1x1_Gate_Expr_LogicalAND", owner = owner }), 40, 0, 6)
BR.transaction(ps, function(tx)
    tx.connect(BR.brick_id(a), BR.output_port(AND, "bOutput"), BR.brick_id(b), BR.input_port(AND, "bInputA"))
    tx.set(BR.brick_id(a), BR.input_port(AND, "bInputA"), BR.wire_bool(true))
    tx.set(BR.brick_id(a), BR.input_port(AND, "bInputB"), BR.wire_bool(true))
end)  -- { WiresConnected = 1, ComponentsChanged = 2, ... }

-- a number
local add = BR.place(BR.builder({ asset = "B_1x1_Gate_Expr_MathAdd", owner = owner }), 80, 0, 6)
BR.set_input(add, ADD, "InputA", BR.wire_double(5))
assert(BR.input_is(add, ADD, "InputA", BR.wire_double(5)))

-- give a plain brick a component
local brick = BR.place(BR.builder({ asset = "PB_DefaultBrick", size = { 5, 5, 6 }, owner = owner }), 120, 0, 6)
BR.transaction(ps, function(tx) tx.attach(BR.brick_id(brick), BR.component_type("Component_BrickPropertyChanger")) end)
```

`BR.input_is` reads through the transaction report: re-setting the current value is
*skipped*, any other value is *changed* (and applied). It raises an error for any other result.
It can't read **wired** inputs: a Set on a wired input is always skipped, which would look like
"already that value". To observe outputs, see [signal bricks](interop.md#reacting-to-component-changes).

### Firing exec gates

| | |
|--|--|
| `BR.trigger(x, y, z)` | place a trigger gate; returns `t` with `t.brick`, `t.connect(target, type, port)`, `t.fire()` |

Every `t.fire()` fires whatever its wire leads to, one tick later. Wire it to any exec input:
Broadcast Chat Message, a Send Custom Event brick, a branch. Connect, then fire from a later
call: a wire isn't live in the tick it was made. Tested on Release-EA3-CL-16507 (one chat line per fire):

```lua
local CHAT = BR.component_type("Gamemode_BroadcastChatMessage"):GetFName():ToString()
local chat = BR.place(BR.builder({ asset = "B_1x1_Gate_Exec_Gamemode_BroadcastChatMessage", owner = BR.owner_index() }), 40, 0, 6)
_G.T = BR.trigger(0, 0, 6)
_G.T.connect(chat, CHAT, "Exec")
-- later
_G.T.fire()
```

## Component data

Every component's settings, not only its wire inputs: bot spawner tuning, custom event names,
button labels. Written with the engine's own property changelists
([format](brickadia-internals.md#property-changelists)).

| | |
|--|--|
| `BR.set_component(handle, type, values)` | set fields; `values` maps field paths to Lua values |
| `BR.get_component(handle, type, path)` | read one field (`"GunSkill"`, `"MoveTarget.X"`) |
| `BR.component_data(handle, type)` | every readable field as a table, or nil if the brick has no such component |
| `BR.component_fields(type)` | `{ { name, type } }` for every field |
| `BR.component_struct(type)` | the component's data struct (a UScriptStruct) |
| `BR.component_address(handle, type)` | where the data lives, for reading it raw |

```lua
local spawn = BR.place(BR.builder({ asset = "B_Bot_Spawn_Point", owner = BR.owner_index() }), 0, 80, 6)
BR.set_component(spawn, "BotSpawn", {
    GunSkill = 0.25,
    bActiveBot = false,
    BotName = "Lua Bot",
    ["MoveTarget.X"] = 100,          -- a field inside a struct field
})
```

Each value is converted to the field's own type, read from reflection:

| Field type | Lua value |
|------------|-----------|
| `BoolProperty` | boolean |
| `Int8Property` ... `UInt64Property`, `ByteProperty` | integer |
| `FloatProperty`, `DoubleProperty` | number |
| `Struct<WireString>` (names, labels, messages) | string |
| a struct (`Struct<Vector>`, ...) | write its fields with a dotted path |

Anything else (arrays, maps, enums, object references) raises an error naming the field and
its type, as does an unknown field. The write applies at once, without a transaction or trust
check (like `BR.place`), and works on a brick's built-in components as well as attached ones.
A mismatch the engine itself refuses is logged under `LogBRPropertyChange` and leaves the
field unchanged. Tested on Release-EA3-CL-16507: bool, uint8, float and WireString fields, several fields at
once, on built-in and attached components.

Reads return booleans, numbers, strings for `WireString` fields, wire values (decoded:
booleans, numbers, strings, `{x, y, z}` vectors; `{ kind = n }` for kinds not decoded yet) and
nested structs as tables; object references and containers read as nil. They are plain memory
reads, cheap enough to run every tick:

```lua
local d = BR.component_data(spawn, "BotSpawn")
print(d.GunSkill, d.BotName, d.MoveTarget.X)
print(BR.get_component(gate, "BrickComponentType_Expr_LogicalAND", "bOutput"))   -- a gate's output
```

## Custom events

Send Custom Event gates reach the receivers whose event name matches. Global events reach
every matching receiver in the world; targeted events reach only receivers on the target
entity (a brick grid: a contraption, vehicle or other dynamic grid).

| | |
|--|--|
| `BR.custom_event(name, opts?)` | place a named sender (and its trigger); returns `ev` with `ev.send(...)` |
| `BR.on_custom_event(name, fn, opts?)` | `fn(data, count)` whenever the event `name` fires; returns a function that stops it |
| `BR.grids()` | every dynamic brick grid entity |
| `BR.brick_grid(handle)` | the grid a brick is on (the global grid or an entity) |

| Option | `custom_event` | `on_custom_event` |
|--------|----------------|-------------------|
| `at = {x, y, z}` | where the sender goes | where the counting gates go |
| `target = grid` | send only to that entity | |
| `entity = grid` | | listen for events sent to that entity |

Without `at`, BR finds free space high above a corner of the map. `ev.send(...)` takes up to 8
wire values for `DataIn1..8`; send from a later call than the one that placed the sender.
`on_custom_event` hears senders built in game as well. `data` holds `DataOut1..8` as Lua values
(unset slots read as 0), and `count` is how many times the event fired since the previous tick
(with `data` from the latest). The handler runs on the game thread a tick or two after the
event.

```lua
-- global
BR.on_custom_event("door_open", function(data, count)
    Omegga.emit("door_open", { by = data[1], times = count })
end)
_G.DOOR = BR.custom_event("door_open")
_G.DOOR.send(BR.wire_string("lever 3"))     -- from a later call

-- one vehicle
local car = BR.brick_grid(some_brick_on_the_car)
BR.on_custom_event("honk", function() print("honk") end, { entity = car })
_G.HONK = BR.custom_event("honk", { target = car })
_G.HONK.send()
```

Tested on Release-EA3-CL-16507: a global listener got `{ "payload", 7 }` with count 1 and a listener for
another name stayed quiet; a targeted send reached the listener on its grid once, while the
same name on a second grid and a global listener stayed quiet.

How it works, since exec signals never reach anything Lua can hook:

- **Listening** places a receiver named `name` and wires its `ExecOut` to a Variable
  Increment gate; BR reads the variable every tick. For an entity, the receiver goes on that
  grid (with `bIsObjectEvent`, which targeted events need), hidden and without collision, in
  the first free spot near the grid's origin; the counter stays on the world grid.
- **Sending to an entity** places a Read Brick Grid gate on the target grid (hidden, no
  collision) and wires its output to the sender's `Target`: a transaction can't set an object
  value, but a wire can carry one, across grids too.

Existing senders and receivers built in game can be renamed with
`BR.set_component(brick, "Event_CustomGlobal", { EventName = "door_open" })`.

## Strings

| | |
|--|--|
| `BR.wire_string(text)` | a String wire value, for string inputs (`Message`, `BotName`, string gates) |
| `BR.wirestring(text)` | the 16-byte `WireString` itself, for raw calls that take one (`BREntityActor:SetEntityTag`, untested) |

Each string is allocated in the game's heap and kept for good (a few bytes each), so make
them when something changes, not every tick.

## Player events

| | |
|--|--|
| `BR.on(event, fn)` | `fn(player, info)` when a player does `event`; returns a function that stops it |
| `BR.EVENTS` | the event names |
| `BR.player_of(obj)` | the PlayerState behind a controller, character, tool or weapon, or nil |
| `BR.on_tick(fn)` | `fn(deltaSeconds)` at the start of every engine tick; returns a stop function |

`player` is the PlayerState (nil for bots). Handlers run on the game thread *before* the
game handles the action, so a brick about to be deleted can still be read.

| Event | `info` | Hooked on | Tested |
|-------|--------|-----------|--------|
| `join`, `leave` | `controller` | `GameModeBase:K2_PostLogin` / `K2_OnLogout` | no (needs a client) |
| `chat` | `message` | `BRPlayerController:ServerPushChatMessage` | yes |
| `typing` | `typing` (bool) | `BRPlayerController:ServerSetTyping` | yes |
| `death` | `character`, `damage`, `damage_type`, `killer` (PlayerState), `cause` | `BRCharacter:MulticastHandleDeath` | yes |
| `damage` | `character`, `damage` | `BRCharacter:MulticastPlayPainSound` | no (no damage on the test map) |
| `emote`, `emote_end` | `character`, `emote` (class name) | `BRCharacter:ServerStartEmoting` / `ServerStopEmoting` | no |
| `interact`, `interact_end` | `character`, `brick`, `nearby` | `BRCharacter:ServerMaybeStartInteract` / `ServerStopAnyInteract` | yes |
| `shoot` | `weapon` (class name) | `BRWeaponBase:MulticastReplicateAcceleratedProjectiles(WithSeed)` | yes, with real players; projectile weapons only |
| `melee_hit` | `weapon`, `position`, `damage`, `backstab`, `actor`, `brick`, and `character` + `player` when a player was hit | `BRWeaponBase:ServerApplyMeleePredictedDamage` | not yet |
| `avatar` | `manager` (their `BRPlayerAvatarManagerComponent`) | `BRPlayerAvatarManagerComponent:ServerUpdatePlayerAvatar` | yes, with real players |
| `projectile_hit` | `projectile` (class name), `position`, `normal`, `bone` (name or nil), then one of `brick`, `entity`, `character` + `player`, or none (the map) | `BRWeaponProjectile:ProcessStop` | fires for real players' shots; the target detection isn't checked yet. Bounces don't fire it |
| `place` | `kind` (`brick`, `entity`, `prefab`), `position`, `orientation`, `color` / `entity` | `BRTool_Placer:ServerPlaceSimpleBrickVolume`, `...EntityVolume`, `ServerPlaceCurrentPrefab` | no (needs a client's tools) |
| `delete` | `kind` (`hammer`, `placer`, `selection`), `brick` | `BRTool_Hammer:ServerHammerBrick`, `BRPlacerControlMode_Delete:ServerHammerBrick`, `BRTool_Selector:ServerDeleteSelection` | no |
| `change` | `kind` (`paint`, `fill`, `apply`, `paste`, `reset`, `remove_component`, `resize`, `rotate`, `direction`), `brick` | painter, applicator and resizer tool RPCs | no |

"Tested" means the hook fired with the right player and details, either for real players on a
live server or for a spawned stand-in character (a chat message, a death, a button press). The untested ones hook
the RPC a real client sends; the payload offsets come from reflection, but they haven't seen a
real call yet. Reload and voice have no server-side RPC (weapon state replicates as a
property, and voice doesn't pass through UFunctions on the server), so they aren't events.

Forwarding to omegga:

```lua
for _, event in ipairs({ "chat", "death", "place", "delete" }) do
    BR.on(event, function(player, info)
        info.player = player and BR.player_info(player).name or nil
        info.character, info.cause, info.killer = nil, nil, nil   -- UObjects don't travel as JSON
        if info.brick then info.brick = BR.brick_info(info.brick).position end
        Omegga.emit(event, info)
    end)
end
```

Shortcuts for interactions:

| | |
|--|--|
| `BR.on_interact(fn)` / `BR.on_interact_end(fn)` | `fn(character, brick, nearby)` / `fn(character)` |
| `BR.on_avatar_change(fn)` | `fn(player, manager)` when a player saves an avatar; the save can't be refused, so to enforce a uniform, set it again on a later tick |
| `BR.interact(character, brick, nearby?)` / `BR.stop_interact(character)` | press a brick as that character |
| `BR.on_call(path, fn)` | `fn(self, params)` before every call of a UFunction, with raw parameter bytes |

`on_call` sees calls that go through ProcessEvent, which includes every RPC a client sends and
every Blueprint event, but not native C++ calling C++.

`projectile_hit` reports the player who fired (`InstigatorState`). The hit result names the struck
actor only through a weak handle Lua can't resolve, so the target is worked out: a hit with a bone
name is the nearest character, otherwise a short trace into the surface finds a brick or entity.

A pistol that builds where it hits, in the shooter's paint (see [Players and teams](#players-and-teams)
for the paint selection):

```lua
BR.on("projectile_hit", function(player, info)
    if not player or info.character then return end
    local p, n = info.position, info.normal
    local x = math.floor((p[1] + n[1] * 5) / 10) * 10 + 5
    local y = math.floor((p[2] + n[2] * 5) / 10) * 10 + 5
    local z = math.floor((p[3] + n[3] * 6 - 6) / 4 + 0.5) * 4 + 6
    local owner = FindFirstOf("BRGameStateBase"):IdOrRegisterBrickOwner(BR.controller(player))
    BR.place(BR.builder({ size = { 5, 5, 6 }, owner = owner }), x, y, z)
end)
```

## Players and teams

Recipes found on a live server, by hand rather than as helpers yet:

```lua
-- size: a replicated float; OnRep applies it on the server too (collision follows)
ch.CharacterScale = 2.0
ch:OnRep_CharacterScale()
ch:ForceNetUpdate()

-- a character with no AI: spawn the figure class with no controller; it stands where it is put
local npc = BR.spawn(BR.character(ps):GetClass())
npc:K2_SetActorLocation({ X = x, Y = y, Z = z }, false, {}, true)
npc.BotName = FText("Claude"); npc:UpdateNametag()
-- turn it with K2_SetActorRotation each tick; a player can take it over:
local pc = BR.controller(ps); pc:UnPossess(); pc:Possess(npc)   -- the old body stays behind

-- a player's paint selection; MaterialIndex is the server's material list index, not
-- BR.MATERIAL, so apply it to a placed brick separately
local sel = ps.ColorSelectionState          -- SelectedColor {R,G,B,A}, MaterialIndex, MaterialAlpha
StaticFindObject("/Script/Brickadia.Default__BrickInstanceStatics"):SetMaterialIndex(
    { Index = string.unpack("<i4", h, 1), Generation = string.unpack("<i4", h, 5) }, sel.MaterialIndex, BR.world_context())
```

`FindFirstOf("BRGameInstance"):IsMaterialIndexUsableForPainting(i)` filters out indexes a player
can't paint with. Avatars live in `UBRPlayerAvatarManagerComponent.CustomizedAvatar` (set with
`UpdatePlayerAvatar`), and `ABRCharacter:BuildAvatarCustomizationFromPlayerParts()` reads one off
any character; copying one this way is untested. Chat accepts rich text markup, for example
`<color="d97757"><b>[Claude]</></>`.

Players are PlayerStates (`ps`). Tested on Release-EA3-CL-16507 with a spawned controller that has a character
(see [internals](brickadia-internals.md#players-and-characters)); a real client's name and id
were not checked.

| | |
|--|--|
| `BR.players()` | PlayerStates of connected clients |
| `BR.find_player(name)` | by user or display name (`BRGameStateBase:FindClientState`), or nil |
| `BR.player_info(ps)` | `{ name, display_name, id, owner, connected, team, alive, health, max_health }` |
| `BR.controller(ps)` / `BR.character(ps)` | the `BRPlayerController` / living `BRCharacter`, or nil |
| `BR.connected(ps)` | whether it is a connected client |
| `BR.team(ps)` | its `BRGameModeTeam`, or nil |
| `BR.teams()` | every team, unaffiliated first |
| `BR.team_info(team)` | `{ id, name, color = {r, g, b, a}, members = {names} }` |
| `BR.join_team(ps, id, respawn?)` | move to team `id` (-1: unaffiliated) |

## Bots

| | |
|--|--|
| `BR.bots()` | live bot pawns (`BP_FigureV2_Bot_C`) |
| `BR.teleport(actor, x, y, z)` | `K2_TeleportTo`, keeps rotation; world units |

A `B_Bot_Spawn_Point` brick spawns a bot on top of itself within a second. It is configured
through its component inputs (`BR.ports("BotSpawn")`): `BotName`, `BotScale`, `MoveTarget`,
`bActiveBot`, `bSpawnEnable`, `AggroRange`, `RunSpeed`, `GunSkill`, `HealthMultiplier`,
`bCanTargetPlayers`, ... Place the spawn brick with `owner = BR.owner_index()` to set them
(`BotScale` and `bActiveBot` tested):

```lua
local spawn = BR.place(BR.builder({ asset = "B_Bot_Spawn_Point", owner = BR.owner_index() }), 0, 80, 6)
BR.set_input(spawn, "BotSpawn", "BotScale", BR.wire_double(2))
BR.set_input(spawn, "BotSpawn", "bActiveBot", BR.wire_bool(false))
```

String inputs take `BR.wire_string`; any field, wire input or not, takes `BR.set_component`.

## Entities

Entities (balls, wheels, vehicles) are `BREntityActor` actors. Tested on Release-EA3-CL-16507.

| `BR.delete_entity(e)` | |

The rest of `BRLuauEntityLibrary` is reflected and callable directly:

```lua
local W = StaticFindObject("/Script/Brickadia.Default__BRLuauWorldLibrary")
local E = StaticFindObject("/Script/Brickadia.Default__BRLuauEntityLibrary")
local cls = W:FindEntityType("Entity_Ball", BR.world_context())   -- Entity_Ball, Entity_Wheel_Caster, ...
local ball = BR.spawn_entity(cls, 0, 0, 300)

```

custom properties only exist as gates (`Exec_Entity_Set/Get/RemoveCustomProperty`); drive them
with a trigger and `BR.wire_string` keys.

## Raycasts

| | |
|--|--|
| `BR.raycast(origin, direction, opts?)` | `nil`, or `{ position, normal, distance, brick, entity }` |
| `BR.sweep(origin, direction, radius, opts?)` | the same with a sphere |

Vectors are `{x, y, z}` in world units (X and Y match brick grid units); the direction needn't
be normalised. `opts`: `distance` (default 100000), `channel` (default `"Visibility"`),
`targets` (default `"All"`), `complex`. Names are in `BR.TRACE_CHANNEL` and `BR.TRACE_TARGETS`;
targets are bits, so `BR.TRACE_TARGETS.Brick | BR.TRACE_TARGETS.PhysicsBody` works too. `brick`
is a handle and `entity` an actor, each nil when the hit wasn't one. Tested on Release-EA3-CL-16507:

```lua
local hit = BR.raycast({ 0, 8000, 500 }, { 0, 0, -1 })
-- { position = {0, 8000, 12}, normal = {0, 0, 1}, distance = 488, brick = <handle> }
BR.brick_info(hit.brick).position   -- {0, 8000, 6}
BR.raycast({ 0, 8400, 800 }, { 0, 0, -1 }).entity:GetClass()   -- BP_Entity_Ball_C
```

- A brick has no collision until the tick after it is placed: a ray in the same call goes
  through it.
- The `BrickInteractive` channel ignores plain bricks.
- The plate counts as a hit (no `brick`, no `entity`).

## Calling any UFunction

When every parameter is a reflected type, call it directly: `obj:FunctionName(args...)`. When
one is an opaque struct, use the raw path:

| | |
|--|--|
| `BR.call(target, class, fn, args)` | `args` maps param names to bytes; returns a table of each param's bytes after the call. `class` is a Brickadia class or `"Package.Class"` (`"Engine.KismetStringLibrary"`) |
| `BR.ptr(obj)` / `BR.obj(bytes)` | a UObject as 8 pointer bytes and back |
| `BR.bool`, `BR.i32`, `BR.ivec(x, y, z)` | small codecs |
| `BR.fstring(bytes)` / `BR.ftext(bytes)` | decode FString / FText bytes (ASCII) |

Under it are the native helpers every mod has (from the BrickadiaBridge C++ mod):

| | |
|--|--|
| `__fn_layout(path)` | a UFunction's parameter offsets and sizes |
| `__raw_call(target, path, bytes)` | call it with a raw parameter buffer; returns the buffer after the call |
| `__addr(obj)` / `__obj(addr)` | UObject to address and back |
| `__fname(text)` | an FName as an integer |
| `__peek(addr, len)` | read memory |
| `__alloc(bytes)` / `__free(addr)` | scratch memory the engine only reads during a call |
| `__game_alloc(bytes)` | memory in the game's heap, for things the engine takes over and frees |
| `__on_call(path, fn)` | raw ProcessEvent hook (`BR.on_call` wraps it) |
| `__on_tick(fn)` | `fn(deltaSeconds)` every engine tick (`BR.on_tick` wraps it) |
| `__component_data(handle)` | address of a component's data from its 8-byte handle, or nil |
| `__bridge_listen(name, fn)` / `__bridge_send(conn, line)` | the omegga socket ([interop.md](interop.md#transport)) |

Raw-call buffers are never destructed: FString and TArray results leak a little memory per
call, which is fine for occasional use but not for per-tick loops. Typings for all of this are
in [`types/omegga.lua`](../types/omegga.lua) ([editor completion](#editor-completion)).

```lua
-- a brick's colour: GetColor returns an FColor (bytes B, G, R, A)
local lib = StaticFindObject("/Script/Brickadia.Default__BRLuauBrickLibrary")
local b, g, r, a = string.byte(BR.call(lib, "BRLuauBrickLibrary", "GetColor", { Self = handle }).ReturnValue, 1, 4)
```

`__peek` and a wrong layout can crash the server; test new calls on a scratch server
([exploring.md](exploring.md)).
